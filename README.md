# VESC Бортовой компьютер

Приборная панель для электросамоката на двух VESC (Dualtron Achilleus · 60V 16S · 2× Flipsky 75100 Pro V2). Работает в браузере телефона и ставится на рабочий стол как приложение (PWA). Подключение по Bluetooth LE или USB.

**Открыть:** https://sanlaran.github.io/vesc/ · без самоката можно нажать **«Демо»**: два виртуальных 75100 на FW 6.05.

## Что умеет

**Приборка**
- Строгий чёрный интерфейс: квадратные формы, тонкие линии, белый текст. Цвет только по смыслу: зелёный — рекуперация, жёлтый — внимание, красный — опасность. Есть светлая тема.
- Крупные цифры скорости, пиковая скорость и знак ограничения. Под ними полоса мощности от нуля (тяга вправо, рекуперация влево), ток АКБ и duty. Скорость берётся с VESC или с GPS.
- Заряд по кривой напряжения покоя: просадка под нагрузкой компенсируется, сопротивление пакета оценивается на ходу. Запас хода считается по реальному расходу Вт·ч/км.
- Пробег и одометр идут по тахометру VESC, энергия по счётчикам Вт·ч. Интегрирование скорости не используется.
- Виджеты (порядок и видимость настраиваются):
  - моторы перед/зад: ток фазы, ток АКБ, ток FW, duty, скорость колеса, пробуксовка;
  - батарея: просадка, напряжение ячейки, R пакета;
  - расход и запас хода;
  - разгон 0–30/50/60/80/100;
  - график за 60 с;
  - температуры с отметками, с которых VESC режет ток;
  - бортовой компьютер поездки.
- Предупреждения:
  - ошибки VESC с правильными названиями;
  - потеря телеметрии;
  - перегрев;
  - превышение тока этапа BMS;
  - отсечка АКБ;
  - разный FW на моторах и FW в 1WD.

  На критичных предупреждениях телефон вибрирует.
- HUD в альбомной ориентации на весь экран, блокировка экрана от случайных касаний (снимается удержанием), Wake Lock.

**Режимы езды** (переключаются на ходу)
- BASE: собственные лимиты VESC. ECO, CITY, SPORT и TURBO: потолок скорости, мощности и тока АКБ, процент тяги и торможения. Профили редактируются во вкладке «Тюнинг».
- 2WD / Перед / Зад и доля переднего мотора в 2WD. В 1WD свободное колесо не тянет, но тормозит.
- **LIM**: ограничитель скорости (по умолчанию 25 км/ч) поверх любого режима.
- Режимы отправляются командой `SET_MCCONF_TEMP` и живут только в RAM, во flash ничего не пишется. Лимиты никогда не превышают то, что настроено в самом VESC. После выключения контроллер возвращается к своим настройкам, а приборка применяет режим снова при подключении.

**Ослабление поля (FW)**: вкладка «Тюнинг», подробнее ниже.

**Поездки**: Яндекс Карта, GPS-трек с раскраской по скорости, запись, история, экспорт GPX, маршрут по тапу на карте.

**Настройки**
- Подключение и CAN ID (второй VESC находится автоматически через `PING_CAN`).
- Параметры самоката. Их можно взять прямо из VESC, а диаметр колеса откалибровать по GPS.
- Экран, чек-лист сборки и BMS, сброс данных.

## Подключение

| Режим | Когда |
| --- | --- |
| **1 BLE + CAN** | Модуль на master-VESC, второй опрашивается по CAN. Рекомендуется. |
| **2 × BLE** | Свой BLE-модуль на каждом VESC, подключаются по очереди. |
| **USB (OTG)** | Кабель к master-VESC. Chrome на Android или ПК. |
| **Демо** | Виртуальная пара контроллеров, можно проверить всё, включая запись FW. |

- **Android:** Chrome.
- **iPhone:** Safari и Chrome не поддерживают Web Bluetooth, используйте браузер Bluefy.
- Страница должна быть открыта по HTTPS.
- Приборка опрашивает оба контроллера 10 раз в секунду. В полёте всегда только один запрос, ответы сверяются по `controller_id`.

## Ослабление поля (Field Weakening)

1. Остановитесь. Запись идёт во flash, поэтому на ходу она заблокирована.
2. **Тюнинг → Ослабление поля · FW**:
   - включите переключатель;
   - задайте **ток FW** ползунком, полем или пресетом 10–40 А (максимум ≈60% тока мотора);
   - задайте **старт по duty** (60–95% от max duty);
   - выберите, куда писать: **Оба** / Перед / Зад.
3. Нажмите **«Записать FW … А»**, отметьте «Понимаю риски» и подтвердите.

Что происходит при записи:
- приборка ещё раз убеждается, что оба колеса стоят и мотор в режиме FOC;
- читает конфигурацию;
- меняет **только** поля `foc_fw_current_max` и `foc_fw_duty_start`, а лишние изменения байтов проверяются;
- пишет `SET_MCCONF`, перечитывает и сверяет результат;
- затем снова применяет текущий режим езды.

**Выключить FW** означает записать 0 А: прошивка отключает FW при токе ниже `cc_min_current`.

Безопасность:
- Начинайте с 10–20 А. Первый запуск делайте на поднятом колесе, потом на небольшой скорости.
- **Записывайте одинаковый FW на оба мотора.** Выше «родной» максималки мотор без FW (или с меньшим FW) отдаёт ток через диоды и тормозит. По той же причине **не ездите с FW в 1WD**. Приборка предупреждает об обоих случаях.
- FW греет мотор и контроллер и повышает расход. Если VESC уйдёт в ошибку на скорости выше «родной», возможны резкое торможение и бросок напряжения. Не используйте FW на почти пустой АКБ и с BMS без запаса по зарядному току.

## Что приборка пишет в VESC

- `SET_MCCONF_TEMP` (RAM): режимы езды, 2WD/1WD, LIM.
- `SET_MCCONF` (flash): только по кнопке записи FW и только на месте.

Приборка **не управляет моторами** с телефона: нет команд тока, тормоза или «ручника».

## Проверка на самокате

1. Поднимите колёса. Подключитесь и проверьте, что видны оба контроллера и CAN ID определился.
2. Переключайте BASE → ECO → SPORT, 2WD → Перед → Зад и LIM. Статус должен быть «Применено в VESC». Кнопка «Перечитать» в «Тюнинг → Контроллеры» покажет новые лимиты в RAM.
3. Запишите FW 10 А на оба мотора. Проверьте перечитанное значение, затем раскрутите колесо на весу.
4. Короткий заезд: скорость, заряд, температуры, пробег сверьте с VESC Tool. Откалибруйте колесо по GPS.
5. Только потом постепенно повышайте ток FW, следя за температурами.

## Разработка

```bash
npm ci
npm run dev      # http://localhost:5173/vesc/
npm test         # протокол, раскладки MCCONF, режимы и запись FW на виртуальных VESC
npm run build
```

- `src/protocol`: кадры VESC, раскладки MCCONF для FW 5.03–7.x, транспорт BLE/USB, шина с опросом и CAN.
- `src/sim`: виртуальные VESC для демо и тестов.
- `src/state`: конфиг, режимы езды, расчёт поездки и батареи.
- `src/hooks/useVescSession.ts`: подключение, синхронизация, режимы, запись FW.
- PNG-иконки PWA лежат в `branding/icons` (base64), собираются из `branding/make-icons.mjs` и попадают в сборку через `vite.config.ts`.

## GitHub Pages и ключ Яндекс Карт

GitHub Actions прогоняет тесты, собирает сайт и публикует `dist` на Pages. Ключ Яндекс Карт задан как клиентский ключ в `src/config.ts`. При необходимости его можно переопределить через `VITE_YANDEX_MAPS_API_KEY` во время сборки.

Ключ JavaScript API неизбежно доступен браузеру. Ограничьте разрешённые HTTP referrer-домены в кабинете Яндекс Cloud, включая `https://sanlaran.github.io/*`. Не используйте клиентский ключ с неограниченными правами.
